Você deverá ler todas as tasks que estão neste backlog. Cada uma tem sua especificação, porém todas devem seguir as orientações padrões desta task principal de configuração:

# Não rode testes:
Testes não são utilizados no projeto, então não há motivo para validar testes. Não perca tempo escrevendo e nem rodando. 

# Orquestre agentes:
Eu quero que você orquestre a maioria das tasks. Coloque agentes diferentes para trabalhar em cada tarefa e, de acordo com o nível de complexidade, utilize modelos adequados e referentes àquela necessidade. Exemplo: haiku faz uma coisa X, que é simples e o opus faz algo mais complexo. 
Além disso, separe funções pra cada agente: mantenha o máximo de agentes de execução em paralelo, cada um realizando mini tarefas, mas também mantenha agentes em cada função de testar, validar, etc.

# Paralelismo
Trabalhe com o máximo de agentes em paralelo possível.

# Backlog
Quebre cada tarefa do backlog anotada aqui em subtarefas menores, para dar mais precisão e não precisar matar uma formiga com uma bazuca. Assim, você entende a complexidade de cada tarefa e designa um agente adequado para realizar a mesma. 

# Custo
Tome cuidado com o custo de limite. Procure gastar o mínimo de tokens possíveis. Seja econômico, mas eficaz. Quando a sessão estiver nos 90% de uso, prestes a acabar, pare onde estava e guarde a memória de onde parou para prosseguirmos depois. 

# Explicações
Seja breve, claro e direto nas explicações, não precisa escrever grandes textos para falar comigo, perguntar, etc. Só seja direto, claro ,e explique de uma forma que eu iria entender. 

# Testes
Se necessário, somente se for necessário, você pode abrir o navegador no meu pc e visualizar a página do bot para ver se está tudo certo. 

# Pull Request
Ao terminar cada task, ou pequena task, para não perdermos tempo, já pode subir uma pull request. 
Na verdade, apenas para tasks significativas, exemplo: corrigi um bug. Jà crie uma pull request. Pq assim, eu consigo ir subindo e testando as correções e implementações assim que você as termina, sem precisar esperar vc terminar todas as tasks do backlog. Então, terminou algo que significa algo, significativo, já faz uma pull request.
